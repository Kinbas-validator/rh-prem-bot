# RWA Premium Monitor для Telegram

Бот отслеживает всплески объёма Premium на **Lighter / Robinhood Chain**. Сообщения и таблица показывают объём в минуту, среднее, xN, долю Premium, направления, число аккаунтов, «Подробнее», таблицу лидеров, периоды **1м / 5м / 15м / 60м**, обновление и кнопки оповещений по тикерам.

По умолчанию выбраны **RWA с категориями STOCK или PRE_IPO**. Список берётся из самой биржи и обновляется каждые 15 минут. На момент проверки это 34 рынка, включая OPENAI, ANTHROPIC, NVDA, TSLA, AAPL, SPCX и SHEIN. Ключи от биржи и кошелёк не нужны.

## Ubuntu VPS — установка одной командой

В интерактивном SSH-терминале на VPS выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Kinbas-validator/rh-prem-bot/main/bootstrap.sh | sudo bash
```

Он сам установит Python/зависимости, запросит токен, chat ID и настройки мониторинга, создаст systemd-сервис и включит автозапуск. Нужна Ubuntu 22.04+ с systemd. Из распакованного исходного проекта та же установка запускается командой `sudo bash install.sh`.

Команда скачивает опубликованный релиз и проверяет SHA256; в GitHub должен быть опубликован релиз с установщиком и контрольной суммой. Переносить файлы вручную и устанавливать Git на VPS не требуется. Установщик не вызывает APT, не меняет Docker и другие службы. Python и библиотеки устанавливаются отдельно в `/opt/rh-prem-bot`. Для службы заданы лимиты CPU 50% одного ядра, памяти 256 МиБ и swap 64 МиБ. Диск, сеть и ресурсы установки остаются общими с другими приложениями.

После установки можно закрывать SSH. Управление: `sudo rh-prem-bot status`, `sudo rh-prem-bot logs`, `sudo rh-prem-bot restart`. Обновление с сохранением настроек и базы:

```bash
sudo rh-prem-bot update
```

[Подробная инструкция](docs/INSTALLATION.md) · [Как публиковать обновления](docs/DEVELOPMENT.md).

## Локальный запуск без установки сервиса

Нужны Linux/macOS (для Windows — WSL), Python **3.12+**, доступ к интернету. Зависимости устанавливаются автоматически; при наличии `uv` используются зафиксированные версии из `uv.lock`.

1. Создайте своего бота в [@BotFather](https://t.me/BotFather) командой `/newbot` и скопируйте токен.
2. В папке проекта выполните:

   ```bash
   ./start.sh setup
   ```

   Введите токен; мастер проверит его, попросит отправить `/start` своему боту и определит ID личного чата. Можно вместо этого указать числовой ID вручную. `.env` сохраняется с правами `600`. Если файл уже есть, мастер его не перезаписывает.

3. Запустите:

   ```bash
   ./start.sh run
   ```

4. Отправьте `/start` в Telegram. Появится таблица как на втором изображении. Переключайте периоды, нажимайте обновление. **🔊 возле тикера означает, что сигналы по нему включены**. Кнопка тикера переключает оповещения только для этого чата. `/menu` открывает меню, `/help` — команды.

Таблица доступна сразу; на старте показывает накопленную часть истории с отметкой о прогреве. Автоматические сигналы включаются после **11 минут непрерывного наблюдения**: 10 минут для среднего плюс минутное окно. После разрыва соединения этот период набирается заново. Для полного периода таблицы 60м нужен час сбора.

Самостоятельно получить ваш токен Telegram невозможно. Без него доступны полноценный живой мониторинг в консоли, диагностика и тесты. Реальная отправка в Telegram требует настройки выше.

## Как пользоваться

| Команда | Действие |
| --- | --- |
| `/start`, `/top` | Лидеры Premium за 5м |
| `/top 1`, `/top 15`, `/top 60` | Выбрать период таблицы |
| `/menu` | Главное меню |
| `/stats OPENAI` | Текущее окно по тикеру |
| `/markets` | Все отслеживаемые рынки |
| `/status` | Соединение, прогрев, переподключения, очередь доставки |
| `/settings` | Действующие пороги |
| `/reset` | Вернуть пороги из `.env` |
| `/set volume 10000` | Минимальный Premium-объём **за окно**, в долларах |
| `/set multiplier 3` | Минимальное превышение среднего |
| `/set share 0.5` | Минимальная доля Premium, от 0 до 1 |
| `/set accounts 2` | Минимум Premium account index |
| `/set cooldown 300` | Интервал между сигналами по одному тикеру, секунды |
| `/pause`, `/resume` | Пауза/возобновление сигналов; сбор данных продолжается |
| `/test` | Помеченное тестовое сообщение с синтетическими данными |

Команды изменения настроек и кнопки включения оповещений доступны только `TELEGRAM_ADMIN_IDS`. Ответы выдаются только чатам из `TELEGRAM_CHAT_IDS`. Для групп укажите отрицательный chat ID и положительный личный user ID администратора; дайте боту право отправлять сообщения.

## Настройки

В `.env.example` перечислены все параметры. `.env` можно создать и вручную:

```bash
cp .env.example .env
chmod 600 .env
```

Заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS`, `TELEGRAM_ADMIN_IDS`. Для личного чата последние два значения одинаковые. Получателей можно перечислить через запятую.

По умолчанию: окно 60с, среднее за предшествующие 30 минут, минимальный прогрев среднего 10 минут, x3, Premium ≥10 000$ за окно, доля ≥50%, ≥2 Premium-аккаунтов, cooldown 300с. Применяются все условия одновременно. Нижняя граница среднего для xN — 1 000$/мин, что ограничивает сигналы при почти нулевом фоне.

Сохранённые через `/set` пороги имеют приоритет над `.env`. `/reset` возвращает значения `.env`, прочитанные при запуске. Остальные настройки читаются из `.env` после перезапуска.

Выбор инструментов:

```dotenv
# Все акции и pre-IPO (по умолчанию)
MARKETS=
RWA_CATEGORIES=STOCK,PRE_IPO
MARKET_TYPES=perp

# Только отдельные акции/pre-IPO:
# MARKETS=OPENAI,ANTHROPIC,NVDA

# Весь раздел RWA, включая QQQ/SPY, ETF и металлы:
# RWA_CATEGORIES=

# Также spot (отдельные рынки с отдельными объёмами):
# MARKET_TYPES=perp,spot
```

Явно заданный тикер должен удовлетворять RWA-фильтрам, иначе запуск завершится понятной ошибкой. Биржевые категории используются как есть: например, SHEIN сейчас имеет STOCK, OPENAI — STOCK/PRE_IPO. Жёсткого списка компаний в коде нет.

## Что означают показатели

- `Premium` определяется **по ставкам maker_fee/taker_fee конкретной исполненной сделки**, согласно тарифам именно Robinhood-инстанса. Plus и платный TWAP Standard распознаются отдельно. Это вывод по тарифу, а не чтение приватного флага аккаунта.
- Одна сделка считается один раз, даже если оба участника Premium. Используется `usd_amount` биржи с точностью до микродоллара.
- `prem→stand` означает **maker Premium → taker Standard**. Это роли исполнения, а не направление движения денег и не сигнал Long/Short. С `FLOW_DIRECTION=seller_buyer` можно переключить на продавец → покупатель. Из снимков нельзя достоверно установить семантику стрелок оригинального бота.
- Участие Premium с Plus/неизвестной ставкой выделяется отдельной строкой. Сумма трёх основных направлений может поэтому отличаться от общего Premium-объёма.
- Число аккаунтов — уникальные **account index** за окно. Субаккаунты одного владельца считаются отдельно.
- Ликвидации, ADL и settlement исключены. Неизвестные ставки не объявляются Premium. Поле `account_type` публичного аккаунта для тарифа не используется.
- В таблице `Prem`/`Vol` — суммы за выбранный период, делённые на число минут. В «Подробнее» — сохранённые данные именно того сигнала, а не изменившаяся текущая статистика.

Алгоритм и оформление восстановлены по изображениям. Скрытые пороги, точный период среднего и действия кнопок оригинала недоступны; здесь они явно определены и настраиваются. Цвета пузырьков, шрифт, ширина строк и округление кнопок задаются клиентом и темой Telegram. [Локальный макет](docs/preview.html) показывает структуру сообщений на синтетических данных.

## Проверка и работа без Telegram

```bash
./scripts/test.sh
./start.sh doctor
./start.sh smoke --seconds 60 --report data/live-smoke.json
./start.sh monitor
./start.sh demo
```

`smoke` использует временную изолированную базу, настоящий публичный WebSocket, реальные RWA-сделки и не отправляет сообщения. Для проверки полного прогрева: `--seconds 720`. `monitor` постоянно пишет реальные сделки в `data/bot.sqlite3` и выводит обнаруженные сигналы в консоль. `doctor` проверяет REST, WS и, если настроен токен, Telegram `getMe`, без отправки сообщений.

Результаты разработки: [исследование API](docs/RESEARCH.ru.md), [отчёт тестирования](docs/TEST_REPORT.md), [отчёт живой проверки](docs/live-smoke.json).

## Управление службой и данными

Службой управляет systemd. Установщик сам создаёт пользователя и пути; `scripts/rh-prem-bot.service` показывает её настройки для справки. Обычно достаточно команды `rh-prem-bot`; стандартные команды systemd также работают:

```bash
sudo systemctl status rh-prem-bot
sudo systemctl restart rh-prem-bot
sudo journalctl -u rh-prem-bot -f
```

Не запускайте одновременно терминальный `run` и сервис с одним Telegram-токеном. Защита от второго процесса действует на один `DB_PATH`; два разных проекта с одним токеном вызовут конфликт Telegram 409.

`./start.sh health` возвращает код 0, если процесс недавно обновил состояние, соединён и получил все подписки; код 1 — иначе. `/status` дополнительно показывает готовность аналитики. Для диагностики `DB_PATH` должен совпадать с работающим процессом.

На VPS конфигурация находится в `/etc/rh-prem-bot/bot.env`, а сделки, настройки, сигналы и очередь — в `/var/lib/rh-prem-bot/bot.sqlite3`. При локальном запуске используется `data/bot.sqlite3`. Старые сделки/сигналы удаляются после 7 дней (параметр `RETENTION_DAYS`). Делайте резервную копию SQLite при остановленном боте либо через SQLite backup API, не копируйте отдельно активный файл без WAL. Объём диска зависит от активности рынков.

Повторная доставка после 429/сбоев хранится в базе. Сигналы старше 15 минут не отправляются. После неопределённого сетевого таймаута Telegram может принять сообщение, но не вернуть ответ: повторная попытка в редком случае создаёт дубликат; Bot API не поддерживает ключ идемпотентности. Обычные повторы сделок и cooldown защищены SQLite.

При изменении тарифов биржи проверьте `models.py` и [официальную таблицу RH](https://apidocs.rh.lighter.xyz/docs/account-types). Известные ставки сохраняются вместе с версией тарифной модели; неизвестные видны в подробной статистике. Устойчивая к сетевым сбоям работа не означает восстановления всей истории во время простоя: после разрыва бот заново прогревается, не подменяя неполную историю полным объёмом.
