# Обновление кода и публикация релиза

Основная ветка — `main`. VPS устанавливает **опубликованные релизы**, а не произвольное состояние ветки. Изменение README или незавершённый коммит не обновляют установленного бота автоматически.

После доработки:

1. Запустить `./scripts/test.sh` и ShellCheck.
2. Изменить версию в `pyproject.toml` и `src/rh_prem_bot/__init__.py`; выполнить `uv lock`.
3. Обновить `docs/RELEASE_NOTES.md` по итоговому поведению.
4. Сделать коммит и отправить `main`.
5. Создать тег `vX.Y.Z`, соответствующий версии, и отправить его в GitHub.

Например, для следующего исправления:

```bash
git push origin main
git tag v1.2.1
git push origin v1.2.1
```

Workflow `Publish release` проверит версию, выполнит тесты, соберёт установщик и контрольную сумму, загрузит их в черновик релиза и затем опубликует его. Релиз, не прошедший тесты, не становится доступным для обновления VPS. Опубликованные версии не перезаписываются: исправление получает новый номер.

После успешной публикации на VPS достаточно:

```bash
sudo rh-prem-bot update
```

Токен GitHub для публичного репозитория на VPS не нужен. GitHub Actions получает временный `GITHUB_TOKEN` с правом записи содержимого только для публикации релиза. Постоянные токены, SSH-ключи и Telegram-токен в workflow не задаются.

Для локальной проверки сборки: `.venv/bin/python scripts/build_installer.py`. Файлы появляются в `dist/` и не коммитятся. Перед публикацией GitHub автоматически собирает их заново из помеченного тегом кода.
