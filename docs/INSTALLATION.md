# Установка на Ubuntu VPS одной командой

В интерактивном SSH-терминале на VPS выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/Kinbas-validator/rh-prem-bot/main/bootstrap.sh | sudo bash
```

Скрипт скачает **опубликованный релиз** с GitHub, проверит контрольную сумму SHA256 и запустит мастер. Публичный репозиторий не требует GitHub-токена на сервере. Релиз должен содержать `rh-prem-bot-installer.run` и `rh-prem-bot-installer.run.sha256`; наличие исходного кода в `main` само по себе недостаточно.

Отдельно распаковывать файл, устанавливать Python, создавать виртуальное окружение, пользователя или редактировать service-файл не нужно. Альтернатива при ручном скачивании — `sudo bash rh-prem-bot-installer.run`. Если у вас весь исходный проект, используйте `sudo bash install.sh`.

Нужна **Ubuntu 22.04 или новее с systemd**, доступ в интернет, root/sudo и стандартные утилиты `curl`, `xz`, `flock`, `runuser`, `useradd`, `sha256sum`, `nice`. Установщик проверяет их наличие; если чего-то нет, сообщает об этом и не запускает APT автоматически. SSH-терминал должен быть интерактивным. Входящие порты открывать не требуется: бот сам подключается к бирже и Telegram.

## На сервере уже есть другие боты и Docker

Версия 1.2 не вызывает APT и не устанавливает пакеты в системный Python. Python 3.12, виртуальное окружение, библиотеки и кэш находятся внутри `/opt/rh-prem-bot`. Docker, контейнеры, их сети/volumes, firewall и файлы других приложений установщик не меняет. Перезапускается только `rh-prem-bot.service`; перезагрузка сервера не выполняется.

Используйте отдельный Telegram-токен для этого проекта. Один токен нельзя одновременно отдавать двум разным работающим ботам: их запросы обновлений будут конфликтовать. При штатном обновлении собственный токен этого бота сохраняется.

Для службы по умолчанию настроены: CPUQuota=50% одного ядра, MemoryHigh=192 МиБ, MemoryMax=256 МиБ, MemorySwapMax=64 МиБ, TasksMax=64, Nice=10 и пониженные CPU/IO weights. Значение CPUQuota относится к одному ядру, а не ко всем ядрам сервера. Работа ограничителей зависит от поддержки cgroups ядром; [описание systemd resource control](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html) объясняет их действие.

Это не нулевая нагрузка: диск, сеть и ресурсы установки остаются общими. Установка выполняется с пониженным CPU-приоритетом и ограниченной параллельностью; SQLite и журнал продолжают занимать место. Старые версии программы очищаются после успешного обновления, сохраняются текущая и предыдущая. Данные SQLite хранятся согласно `RETENTION_DAYS`; контролируйте свободный диск на небольшом VPS.

## Что спросит мастер

1. **Токен** из @BotFather; ввод скрыт.
2. **Chat ID**. Можно просто нажать Enter и отправить `/start` своему боту — мастер найдёт личный чат. Для группы введите отрицательный ID группы и затем свой положительный user ID администратора.
3. **Какие RWA отслеживать**: акции/pre-IPO или весь RWA, включая ETF и металлы.
4. **Тикеры** через запятую; Enter — все выбранные рынки.
5. **Минимальный Premium-объём за минуту** — по умолчанию 10 000$.
6. **Множитель среднего объёма** — по умолчанию x3.
7. **Минимум Premium-аккаунтов** — по умолчанию 2.
8. **Пауза между сигналами одного тикера** — по умолчанию 300 секунд.

Значения по умолчанию принимаются нажатием Enter. Список тикеров и доступ к Telegram/бирже проверяются до переключения сервиса. В Telegram придёт сообщение, подтверждающее доступ к выбранному чату. Сообщение ещё не означает завершение установки: дождитесь в SSH строки **«Готово! Бот установлен и работает как сервис»**.

После установки отправьте `/start` боту для таблицы. Автоматические сигналы включаются после примерно 11 минут накопления данных. Теперь можно закрывать SSH; сервис запускается автоматически при перезагрузке VPS.

## Управление

```bash
sudo rh-prem-bot status
sudo rh-prem-bot logs
sudo rh-prem-bot health
sudo rh-prem-bot update
sudo rh-prem-bot restart
sudo rh-prem-bot stop
sudo rh-prem-bot start
```

`logs` показывает журнал в реальном времени; Ctrl+C завершает просмотр, бот продолжает работать. `health` проверяет соединение и все подписки, готовность аналитики дополнительно видна в Telegram `/status`.

Повторно пройти мастер:

```bash
sudo rh-prem-bot setup
```

При этом сервис остановится на время ввода токена и проверки. Сохранённые ранее через `/set` пороги сбросятся, чтобы применились новые значения мастера. При обычном обновлении без изменения конфигурации Telegram-настройки сохраняются.

## Где находятся файлы

| Назначение | Путь |
| --- | --- |
| Версии программы и Python 3.12 | `/opt/rh-prem-bot/` |
| Текущая версия | `/opt/rh-prem-bot/current` |
| Конфигурация с токеном | `/etc/rh-prem-bot/bot.env` |
| База сделок, настроек и очередь | `/var/lib/rh-prem-bot/bot.sqlite3` |
| Сервис | `/etc/systemd/system/rh-prem-bot.service` |

Бот работает от отдельного пользователя `rh-prem-bot`. Токен не записывается в service-файл или аргументы процесса. Конфигурацию могут читать root и пользователь бота.

Дополнительные параметры можно изменить через `sudo nano /etc/rh-prem-bot/bot.env`, затем `sudo rh-prem-bot restart`. Пороги, изменённые через Telegram `/set`, имеют приоритет над файлом; `/reset` возвращает значения файла, прочитанные при последнем запуске.

## Обновление

Для следующих обновлений:

```bash
sudo rh-prem-bot update
```

Команда скачает последний опубликованный релиз, проверит SHA256 и передаст установщику `--keep-config`. Повторно вводить токен и chat ID не нужно. Конфигурация и база сохраняются. Пока устанавливаются Python/зависимости, работающий бот продолжает собирать данные. Переключение происходит после предварительной проверки.

Если установлена старая версия без команды `update`, один раз выполните команду установки с GitHub из начала инструкции. Для конкретного релиза можно использовать `curl -fsSL https://raw.githubusercontent.com/Kinbas-validator/rh-prem-bot/main/bootstrap.sh | sudo bash -s -- --version v1.2.0 --keep-config`.

Перед переключением установщик останавливает старый сервис и делает согласованную резервную копию SQLite. Если новая версия не подтвердит соединение со всеми рынками за 90 секунд, установщик восстановит прежнюю версию, конфигурацию, базу и прежнее состояние автозапуска. Проверяется PID новой службы, чтобы старый статус в базе не был принят за успешный запуск. При ошибке до переключения прежняя установка остаётся на месте. Скачанный Python и созданная учётная запись при откате не удаляются; системные пакеты установщик не меняет.

Если нет сети, неверен токен или выбраны несуществующие тикеры, исправьте причину и повторите установку. Если автоматический откат сам завершится ошибкой, установщик напечатает путь резервных файлов и команду проверки сервиса.

Python устанавливается отдельно от системного через [официальный uv](https://docs.astral.sh/uv/guides/install-python/); пути Python и установки uv настраиваются согласно [документации uv](https://docs.astral.sh/uv/reference/installer/). Системный Python Ubuntu не заменяется. Зависимости приложения устанавливаются по `uv.lock`.
